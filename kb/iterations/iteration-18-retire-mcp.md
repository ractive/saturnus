# Iteration 18: Retire saturnus-mcp; Kermit tests on kermit-proto

Read first: `crates/saturnus-mcp/` (all of it, with `tests/e2e.rs`),
`crates/saturnus-objects/`, `kb/iterations/iteration-17-control-api.md`,
`kb/decision-log.md` (iterations 6, 9, 12a, 16 and the entry of
2026-10-05 on the control API), `deny.toml`.

## Context (owner, 2026-10-05)

`saturnus-mcp` is retired; the control API of iteration 17 replaces its
keystroke tools, and the hptx CLI over the serial port replaces its
semantic tools. After this iteration nothing in saturnus depends on hptx:
no `hptx-core` git pin, no `allow-git` entry, no MPL-2.0 exception for
`serialport`.

**Blocked until `kermit-proto` is on crates.io.** The crate's ROM-gated
tests carry most of the end-to-end coverage of the Kermit path. They move
first; the crate is deleted only when its coverage has a new home. Until
`kermit-proto` is published this iteration does not start.

## Outcome

**Inventory** (`saturnus-mcp/tests/e2e.rs`, 10 tests, and where each proof
lives now; all in `crates/saturnus-kermit/tests/e2e.rs` unless noted):

- `hp48sx_keys_stack_and_screen`: keys on the 48SX reach the ROM (6 ENTER
  7 * ENTER), the stack read over Kermit shows them, keys leave server
  mode by themselves. Now `hp48sx_keys_then_kermit_stack`. Dropped: the
  MCP tool list and its refusal text (no MCP); the 131x64 PNG screen,
  covered by the control API's `hp48sx_keys_screen_type_and_snapshot`.
- `hp48sx_eval_and_typed_stack`: eval enters and leaves the server, typed
  results (real, string, list, complex, program, binary with its base),
  SIN(0.5) in RAD, calculator errors with the stack's display, syntax
  errors leave the stack, the typed stack, keys after eval, the eval
  limit (1 s fits a trivial command; a 1 s limit interrupts the 48SX and
  drops the text the ROM puts back). Moved as is.
- `hp48sx_push_and_variables`: push of every object shape round trips
  through binary and text transfers, text that could break out of its
  quotes goes binary or is refused, pop, drop, Too Few Arguments,
  directories and `cd`, set/get/list variables, no temporary variable
  left, the RAM tree matches `G D`, long source travels as a string.
  Moved; the MCP `flags` and `status` tool checks went with the tools
  (the RAM flags are `ram_reads_match_kermit`'s).
- `hp48gx_and_49g_eval`: the same evals on the 48GX and 49G, the 49G's
  exact integers, the limit interrupting both. Moved as is.
- `aplet_models_have_no_semantic_tools`: the 38G, 39G and 40G refuse the
  typed operations. Now `aplet_models_have_no_kermit_server`.
- `hp49g_kermit_host_command_and_stack`: a 49G booted with the server
  runs a host command. Moved as is.
- `summation_benchmark_matches_real_hardware`: TICKS through a host
  command within 5% of the real 48SX, 48GX and 49G (the "Speed" table).
  Moved as is: 95.50 s, 5.93 s, 5.38 s (real 95.5, 5.9, 5.5), the table
  unchanged.
- `aplet_models_type_hello_world`: the 39G's and 40G's alpha letters
  (golden screens). Moved with its goldens; the MCP `type_text` letter map
  is gone, so the test presses ALPHA and each letter's key itself.
- `ram_reads_match_kermit`, `clock_display_keeps_keys_and_time`,
  `decompiler_matches_the_rom`: moved as is (RAM reads through
  `saturnus_objects::UserMemory` directly instead of MCP wrappers).
- Unit tests that depended on the link: `link.rs`' packet classifiers
  moved to `saturnus-kermit::link`; `object.rs`' encoder, sources and
  text tests to `saturnus_objects::transfer`; `semantic.rs`' tests moved;
  `emulator.rs`' state refusal moved (the file-safety checks of
  `save_state` went with the file API: the refgen keeps its state in
  memory); `keys.rs` and `server.rs` tests went with the MCP tools.

`saturnus-refgen` used `Emulator` (boot without autostart, the
deterministic link, start/stop server, send/receive objects, host
commands, eval and clear_stack, save/load state, key scripts and
`with_machine` for the menu crawler), `parse_model` (now
`saturnus_host::model_from_name`) and `object::Object` (now
`saturnus_objects::Object`). All of it is on `saturnus-kermit`; its
`PrivateDir` went away with the state file.

**The host** is `crates/saturnus-kermit` (`publish = false`): a crate
rather than a test directory because `saturnus-refgen` needs it as a
normal dependency; not published because nothing outside the workspace
uses it. The link runs on emulated time only (the client's clock is idle
emulated time), which replaces `MachineTransport::deterministic`.
`first_packet_retries` stays `None`: with `Some(0)` the decompiler oracle
failed when the 48SX NAKed a `C` 11 ms after it went out and
`kermit-proto` resent after its 1 s stale-NAK grace, which `Some(0)` turns
into "too many retries". Trace (link clock in seconds):

```text
 0.000 > \x01& C2_m)\r
 0.011 < \x01# N3\r
 1.011 > \x013 EToo many retries_\r
```

A note for hptx: a NAK of the command packet is not a reply to it, so
`Some(0)` could allow the resend that follows one.

**saturnus-objects additions** (no new dependency, no feature):
`charset::encode_command`; module `transfer` with `Family` (`of`),
`HEADER_LEN`, `binary_header`, `is_binary_file`, `pack`, `unpack`,
`ascii_body`, `is_plain_name`, `decode_file`, `fill_sources`,
`encode_file`, `to_source`.
