# Iteration 13b: Command categories from the ROM's own menu definitions

Needs iteration 12c (name table and decompiler) merged.

## Context (2026-10-05)

- Owner: "Maybe you can decompile the ROM to get the list of commands
  incl. categories?" Tried on the 48SX after 12c: the definitions of
  menus 1 to 59 are the elements of one list in ROM (ROM J: #3B234),
  referenced from `MENU`'s own code; decoding them with the name table
  placed 334 of 397 commands, more accurately than the removed
  key-pressing crawler.
- Iteration 13a ended with categories from the manuals: 240/397 on the
  48SX (115 of them through the 48G reference), 266/517 on the 48GX,
  44/830 on the 49G; the rest carry an editorial group ("ours", printed as
  a group, not a menu) or none (234 on the 49G). The manuals' scans give
  hardware keys, not menu labels.

## Design

- A menu reader in `saturnus-objects` (or beside the name table): locate
  the menu list from `MENU`'s code on each model (a rule that works on the
  48SX, 48GX and 49G; no committed addresses), decode each definition
  (a list of keys, or a program building one; a key is a command, a
  `{ label action }` pair, a submenu, a unit-name string), and return for
  each command the menus it is in, with the menu's label path where
  submenu links give one. Run-time, per loaded ROM, wasm-clean.
- Menu names: the ROM's definitions give labels of keys, not the name of
  the menu itself. Names come from the keyboard legends in the skins
  (which key or shifted key opens which menu number: established by
  observation on the ROM, one table per model generated by a ROM-gated
  test) and from the label of the key that leads to a submenu.
- `saturnus-refgen` gains a `menus` step that writes the per-model menu
  placement into the catalogs; `categories.json` keeps the manuals'
  placement (keyboard keys, cross-check) and gains the ROM's; the
  editorial groups are dropped where the ROM places the command. A
  command the ROM offers in several menus lists them all.
- `saturnus ref` prints `menu:` from the ROM, `key:` from the manual, and
  an editorial `group:` only where neither exists.
