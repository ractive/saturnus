# Iteration 76b: the content pages, found by search and worth reading

The owner (2026-11-16) wants to start promoting Saturnus (a Show HN,
hpcalc.org, forums) and wants the site to be found for searches such as
"hp emulator", "hp 48gx emulator online", "hp 49g emulator mac", and
also for the technical topics: an emulator in Rust, WebAssembly in the
browser, a Tauri desktop app, native apps written in Rust. "Not SEO
nonsense, but useful": every change must make the page better for a
person reading it.

Scope: the landing page (`web/landing/`) and the docs
(`web/docs/pages/`, `web/docs/build.mjs`, `web/docs/markdown.mjs`), the
sitemap and `llms.txt` they produce. The capital S (**Saturnus** in
prose, `saturnus` in identifiers, see
[[iterations/iteration-76a-capital-s]]) is done here for these files.

## Findings that started it

- The landing page's `<title>` and description never say "emulator"; the
  word appears twice on the whole page.
- No structured data (JSON-LD) anywhere.
- The model pages exist (`docs/48gx/` …) but their titles and openings
  are not phrased the way people search ("HP 48GX emulator").
- Nothing on the site tells the technical story (Rust, wasm, Tauri, the
  clean-room method) on a page of its own, which is what HN and r/rust
  readers look for.

## Tasks

- [x] Titles and meta descriptions of the landing page and every docs
  page: name what the page is in the words people search, readable as a
  sentence.
- [x] JSON-LD: `SoftwareApplication` on the landing page (offers free,
  operating systems, the app's URL), `FAQPage` where a page has a real
  FAQ, `BreadcrumbList` on docs pages; generated by `build.mjs`, valid.
- [x] A short FAQ per model page with the questions people really ask
  (where is the ROM, does it run on my Mac/phone, can I move programs to
  my real calculator, what does not work yet), answered from facts the
  repo already documents.
- [x] A page on how Saturnus is built (Rust core, WebAssembly in the
  browser, Tauri desktop app, the clean-room method, the knowledge base)
  for developers.
- [x] Open Graph/Twitter cards per docs page, `<link rel="canonical">`,
  headings in order, image `alt` texts, internal links between the pages.
- [x] Sitemap and `llms.txt` include every new page.

## What was built

- **Titles.** A page's frontmatter may carry `page_title`, the document's
  `<title>` in the words people search with ("HP 48GX emulator for the
  browser, Mac, Windows and Linux"); `title` stays the heading and the
  name in lists. The site's name follows as " · Saturnus" unless the
  title names it. Titles are at most 70 characters, descriptions 70 to
  190, both unique (`web/test/seo.test.mjs`).
- **The FAQ is Markdown.** Each model page has a `## Questions and
  answers` section; every `###` in it is a question. `build.mjs` reads
  it (`faqOf`) for the `FAQPage` block, so the page, its `.md` and the
  JSON-LD cannot differ, and the Markdown stays as written. Rejected:
  shared answers generated by the build, which would have put text into
  the published Markdown that is not in the source.
- **JSON-LD** as data blocks (`<script type="application/ld+json">`),
  which the Content-Security-Policy does not count as scripts:
  `BreadcrumbList` on every docs page, `FAQPage` on the twelve model
  pages and the landing page, `SoftwareApplication` on the landing page
  (written by hand there; the landing page is copied as it is). No
  rating and no review: there is none, so none is claimed.
- **The page for developers** is `web/docs/pages/how-it-is-built.md`
  (`/saturnus/docs/how-it-is-built/`), in the `index` section, linked
  from the docs index, the landing page, the Saturn overview and every
  model page's FAQ.
- **The landing page** says "emulator" in its title, headline and
  description, has a Questions section (six, in the feature cards'
  form) and a paragraph on the technical side.

## Decisions and open points

- The ROM answers say what hpcalc.org's pages say and no more: the 48SX
  and 48GX pages carry HP's permission of mid-2000, the 49G, 38G and
  39G/40G pages offer the file "for use with emulators" (wiki:
  sources/hpcalc-rom-listings). No answer says "legal".
- The docs still link nothing in the wiki (owner, 2026-10-21): the page
  for developers names the public knowledge base and points to the
  landing page, which links it.
- Left out for lack of a documented fact: whether the beeper sounds, and
  which browsers and versions the app needs.
- The landing page's screenshots still show the lower-case wordmark of
  the app; they are redrawn after iteration 76a
  (`web/landing/app-shot.mjs`, `files-shot.mjs`).
- `web/README.md` ("The docs") does not name `page_title` and the FAQ
  section yet: the READMEs are iteration 76a's.
