# Deep review of the whole codebase, 2026-10-07

Owner's request: review the whole codebase, Rust best practices, unsafe code, module structure, and whether anyone could say the project plagiarises other HP calculator emulators. Five reviewers in fresh contexts read the release tree (main plus PR 29): clean-room comparison against the six GPL emulators (the only reader of their sources, writing no code), security (with sub-reviews of the parsers and the web page, several findings reproduced), Rust practices and structure (Opus, and GLM via OpenRouter over the whole tree), and protocol/web/tests/docs. Fixes: [[iterations/iteration-23-deep-review]], PRs 32 and 33.

## Verdicts

- **Plagiarism:** none. Nothing is a derived work of the GPL emulators. The architecture differs from all six (typed instruction decode, daisy-chain memory controller, event-skipping timers, display hold); every table that matches an emulator is forced by the hardware or traced through a wiki citation to HP, Mastracci, the tutorial or the Intel datasheet; where copying could have shown, the data differs (49G flash CFI table, six cycle counts). An 8-word shingle search over the code, kb and wiki against every emulator file found only hardware-forced sequences, two formulas cited to Mastracci and one marked quotation. The weak point was the written rule, which permitted reading the GPL sources; tightened in PR 33. What a hostile reader would point at first: the memory controller's ID codes and priority order, identical to saturnng's table and cited to documents that predate it.
- **Unsafe code:** none (forbidden workspace-wide).
- **Rust:** the core is dependency-free and I/O-free, the hot path does not allocate, no `unwrap`/`expect` outside tests, guest data is handled defensively except the parser findings below. Weaknesses at the crate boundaries: the core's public surface is far wider than any host uses, and the host crate was shaped around the wasm binding.
- **Security:** the control API, token file, serial bridge, Tauri boundary and workflows held up; findings were the parser crashes, the token sent to whoever holds the port, and smaller items below.
